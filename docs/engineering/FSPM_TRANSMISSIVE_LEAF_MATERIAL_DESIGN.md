# FSPM Transmissive Leaf Material Design

Status: Phase 4B Level 2 implemented for scalar source-weighted receiver
transport. Level 3A banded-transport scaffold implemented; Level 3B live
banded receiver execution remains future work.

## Purpose

Design the next FSPM transport step for Rex-derived transmissive Radiance leaf
materials while preserving the current tandem architecture:

* baseline PPFD/uniformity transport remains room plus emitters only.
* FSPM receiver transport remains a separate room plus emitters plus plant scene.
* `plant_surface_flux.json` remains the incident leaf-surface receiver-flux
  artifact.
* `plant_spectral_absorption.json` remains the modeled spectral
  absorbed/reflected/transmitted leaf photon-flux artifact.

## Current Repo Behavior

Plant Radiance geometry is written by
`src/rad_rebuild/radiance/engine/plants/artifacts.py::write_plant_artifacts`,
which calls
`src/rad_rebuild/radiance/engine/plants/radiance_export.py::export_scene_to_radiance`.
The exporter currently emits one material:

```text
void plastic plant_leaf_material
0
0
5 <reflectance> <reflectance> <reflectance> 0.000000 0.000000
```

Every generated leaf polygon references `leaf.radiance_material_id`, currently
`plant_leaf_material`. The browser viewer artifact is generated separately from
the same plant scene, so a transport-only material change can be isolated from
viewer geometry if the implementation avoids changing stable leaf IDs, polygon
IDs, or viewer JSON semantics.

Baseline PPFD octree inputs are built by `_octree_scene_inputs()` in
`src/rad_rebuild/radiance/cli/scripts.py`. That helper intentionally ignores
`plant_rad`, including frozen-room octree cases. The plant-inclusive receiver
scene is built later by `_build_fspm_receiver_octree()` via
`_fspm_receiver_scene_inputs()`, which appends `plants.rad` only for FSPM
receiver tracing. This is the clean hook for transmissive leaf materials.

Receiver samples are generated by
`src/rad_rebuild/radiance/engine/plants/surface_flux.py::build_radiance_receiver_samples`.
Current practical granularity protocol:

* `leaf_centroid`: smoke/debug.
* `leaf_quadrature_4`: development/demo default.
* `mesh_patch`: high-resolution/reference.

Rex optical data are loaded through
`src/rad_rebuild/radiance/engine/plants/optical_profiles.py` and the selected
profile is currently opt-in via `FSPM_LEAF_OPTICAL_PROFILE_ID`. Source spectra
are resolved in `src/rad_rebuild/radiance/cli/scripts.py` through
`_spectral_distribution_from_env()` and, for wavelength-resolved absorption,
`wavelength_photon_distribution_from_curve_data()`.

Level 2 now adds an opt-in receiver-scene-only Radiance `trans` material through
`FSPM_LEAF_RADIANCE_MATERIAL_MODE=rex_source_weighted_trans`. The default
`opaque_occluder` mode preserves the existing `plastic plant_leaf_material`
output in `runtime_state/plants.rad`.

## Level 2 Recommendation

Implement Level 2 before Level 3.

Recommended flag:

```text
FSPM_LEAF_RADIANCE_MATERIAL_MODE=opaque_occluder | rex_source_weighted_trans
```

Recommended default:

```text
opaque_occluder
```

`opaque_occluder` should preserve current behavior. `rex_source_weighted_trans`
should generate a source-weighted broadband Rex leaf material for the FSPM
receiver scene only. It must not affect baseline PPFD/uniformity artifacts.

### Level 2 Hook

Implementation now writes the existing deterministic plant artifacts first, then
optionally writes a receiver-scene-specific plant Radiance file for
`_build_fspm_receiver_octree()`. The runtime shape is:

* keep `runtime_state/plants.rad` deterministic and compatible with existing
  viewer/report artifacts unless explicitly deciding to version its transport
  material metadata.
* add the receiver-only path
  `runtime_state/plants_fspm_receiver_material.rad` when
  `FSPM_LEAF_RADIANCE_MATERIAL_MODE=rex_source_weighted_trans`.
* pass that receiver-only file into `_build_fspm_receiver_octree()`.
* leave `_octree_scene_inputs()` unchanged so baseline heatmaps, overlays,
  fixture scatter, and uniformity outputs remain plant-free.

This avoids changing simulator runtime behavior for users who do not opt in,
keeps viewer/report artifacts stable, and scopes the Level 2 feature to the
FSPM receiver scene.

### Level 2 Weighting Basis

Use PAR 400-700 nm weighting for Level 2.

Reason: the current scalar receiver trace is treated as PAR PPFD. Existing
`plant_spectral_absorption.json` states `scalar_flux_basis:
par_ppfd_umol_m2_s`, and wavelength distributions are normalized so PAR photons
sum to the scalar receiver value. A PAR scalar receiver trace should not use an
ePAR 400-750 nm weighted material by default because that mixes transport and
postprocessing bases. If a future run changes scalar transport to ePAR, that
should be a separate explicit transport-basis flag and metadata change.

Recommended effective coefficients:

```text
R_eff = sum(PAR_source_photon_fraction(lambda) * leaf_reflectance(lambda))
T_eff = sum(PAR_source_photon_fraction(lambda) * leaf_transmittance(lambda))
A_eff = sum(PAR_source_photon_fraction(lambda) * leaf_absorptance(lambda))
```

where `PAR_source_photon_fraction(lambda)` is normalized over wavelengths in the
selected optical profile grid that lie in 400 <= lambda < 700 nm. Because the
Rex profile carries modeled reflectance, transmittance, and absorptance curves,
`R_eff + T_eff + A_eff` should be validated to equal 1 within tolerance after
weighting.

### Level 2 Material Fitting

Treat leaf transmission as diffuse unless reviewed source data justify specular
transmission. Set specular reflection and specular transmission to zero for the
first implementation.

Proposed Radiance material target:

```text
void trans plant_leaf_material
0
0
7 <color> <color> <color> 0.000000 0.000000 <transmitted_diffuse> 0.000000
```

Do not directly place `R_eff` and `T_eff` into the `trans` line without a
Radiance-material fitting helper. The implementation adds a small pure helper
that converts desired diffuse reflectance and diffuse transmittance to Radiance
`trans` parameters, then validates the coefficients before export.

The older candidate formula below is intentionally not used:

```text
color = R_eff / (1 - T_eff)
transmitted_diffuse = T_eff / (1 - T_eff)
```

The implemented diffuse-only neutral-leaf derivation uses Radiance `trans`
arguments:

```text
void trans plant_leaf_material
0
0
7 red green blue spec rough trans tspec
```

General mapping:

```text
A7 = Ts / (Td + Ts)
A6 = (Td + Ts) / (Rd + Td + Ts)
A5 = roughness
A4 = Rs
A1/A2/A3 = color / ((1 - Rs) * (1 - A6))
```

For Level 2:

```text
Rs = 0
roughness = 0
Ts = 0
Rd = R_eff
Td = T_eff
red = green = blue = R_eff + T_eff
spec = 0
rough = 0
trans = T_eff / (R_eff + T_eff)
tspec = 0
```

The helper rejects non-finite values, fractions outside `[0, 1]`, coefficients
that do not sum to 1 within tolerance, `R_eff + T_eff > 1`, and
`R_eff + T_eff <= 0`. Invalid material coefficients fail clearly rather than
being silently renormalized.

`plant_spectral_absorption.json` should remain the detailed source of
absorbed/reflected/transmitted band metrics. Level 2 changes scalar transport
self-shading/transmission; it should not replace wavelength-binned
postprocessing.

## Level 3 Recommendation

Recommended flag:

```text
FSPM_SPECTRAL_TRANSPORT_MODE=scalar_source_weighted | banded_5
```

Recommended initial default:

```text
scalar_source_weighted
```

`scalar_source_weighted` should mean one FSPM receiver trace using the Level 2
source-weighted material. `banded_5` should mean five FSPM receiver traces,
each with a band-specific emitter scale and a band-specific Rex leaf material.
Level 3A only defines, validates, and plans that banded metadata; it does not
run the five receiver traces.

Level 3 bands:

* blue: 400-499 nm
* green: 500-599 nm
* orange: 600-624 nm
* red: 625-699 nm
* far-red: 700-750 nm

Each band should use:

* band-specific source photon flux.
* band-specific effective Rex reflectance/transmittance/absorptance.
* a band-specific FSPM receiver octree or materialized plant file.
* one receiver trace over the selected receiver samples.
* aggregation into `plant_spectral_absorption.json`.

Level 3 must not multiply baseline PPFD/uniformity artifact generation. Only
the FSPM receiver transport loop may multiply by approximately five.

### Level 3A Scaffold

Implemented scaffold pieces:

* `FSPM_SPECTRAL_TRANSPORT_MODE=scalar_source_weighted | banded_5`
* default `scalar_source_weighted`
* exact five-band definitions:
  * blue: 400-499 nm
  * green: 500-599 nm
  * orange: 600-624 nm
  * red: 625-699 nm
  * far-red: 700-750 nm
* PAR band ids: `blue`, `green`, `orange`, `red`
* ePAR band ids: `blue`, `green`, `orange`, `red`, `far_red`
* source scaling basis:
  `source_band_photon_fraction_relative_to_par`

The current scalar receiver basis remains PAR PPFD:

```text
scalar_flux_basis = par_ppfd_umol_m2_s
band_pfd = scalar_PAR_PPFD * (band_photon_integral / PAR_photon_integral)
```

Far-red is planned as an additional ePAR band and is not labeled as PAR.

For each band, the scaffold computes:

* source photon fraction relative to PAR
* band-specific effective reflectance
* band-specific effective transmittance
* band-specific effective absorptance
* corrected diffuse-only Radiance `trans` parameters through the Level 2
  fitting helper

Zero-source band policy:

* if a band has zero source photons, skip material fitting for that band.
* emit zero band metadata.
* set `source_photon_fraction_relative_to_par: 0`.
* set `band_has_source_photons: false`.
* set `receiver_trace_required: false`.
* do not fail the whole plan.

`banded_5` is recognized by config parsing, but live five-band receiver
execution is intentionally not implemented in Level 3A. Runtime receiver
preparation reports a clear validation error if `banded_5` is requested before
Level 3B is implemented.

## Implemented Level 2 Runtime Impact

`opaque_occluder` remains the default and continues to use the existing
`plastic plant_leaf_material` in `plants.rad`.

`rex_source_weighted_trans` writes
`runtime_state/plants_fspm_receiver_material.rad` and passes that receiver-only
file into `_build_fspm_receiver_octree()`. `_octree_scene_inputs()` remains
plant-free, so baseline PPFD, DOU, CV, heatmaps, fixture overlays, 3D scatter,
and assembly-viewer heatmap overlays remain room plus emitters only.

Receiver tracing remains single-pass in Level 2. `plant_surface_flux.json` is
still generated from one FSPM receiver trace, and
`plant_spectral_absorption.json` reuses that surface-flux payload for detailed
wavelength/band absorbed, reflected, and transmitted photon-flux metrics.

## Self-Intersection And Receiver Risks

Current representative receiver samples use local mesh-patch centroids and
light-facing normals with a small normal offset. That avoided opaque-leaf
self-occlusion in Phase 4A. Transmissive leaves reduce hard self-shadowing, but
they do not remove all risks:

* A receiver point too close to its own transmitting polygon may still count
  immediate self-interaction depending on Radiance ray origin behavior.
* `mesh_patch` front/back samples are more likely to expose offset/sign mistakes
  than `leaf_quadrature_4`.
* Diffuse transmission can increase indirect contribution and sensitivity to
  ambient parameters.

Implementation should keep the existing offset strategy initially, then test
the same receiver samples under `opaque_occluder` and `rex_source_weighted_trans`
with a minimal scene. Do not tune offsets using production scenes first.

## Runtime Risk Assessment

Approximate receiver samples for 768 modeled leaves:

* `leaf_quadrature_4`: 3,072 samples per FSPM receiver trace.
* `mesh_patch`: 24,576 samples per FSPM receiver trace.

Expected trace multipliers:

* Level 2 `rex_source_weighted_trans`: still one FSPM receiver trace, but
  Radiance rays may cost more because transmissive/indirect paths can survive
  through leaves.
* Level 3 `banded_5` with `leaf_quadrature_4`: about 15,360 receiver-sample
  evaluations.
* Level 3 `banded_5` with `mesh_patch`: about 122,880 receiver-sample
  evaluations.

Recommendation:

* use implemented Level 2 first with `leaf_quadrature_4`.
* keep `leaf_centroid` for smoke/debug only.
* use `mesh_patch` for final/reference Level 2 outputs when runtime budget
  permits.
* defer Level 3 until Level 2 artifacts, metadata, and live comparisons are
  stable.

## Test Plan

* env/config parsing accepts only `opaque_occluder` and
  `rex_source_weighted_trans`.
* default material mode preserves current `plastic plant_leaf_material` output.
* Rex source-weighted helper computes PAR-weighted `R_eff`, `T_eff`, and
  `A_eff` from a fake optical profile and fake source distribution.
* helper uses `red = green = blue = R_eff + T_eff` and
  `trans = T_eff / (R_eff + T_eff)`.
* helper rejects invalid coefficient sets or values that are not finite
  fractions.
* receiver-only plant `.rad` changes do not alter viewer JSON, plant manifest
  IDs, or baseline octree inputs.
* `_octree_scene_inputs()` remains plant-free for baseline PPFD/uniformity.
* `_fspm_receiver_scene_inputs()` receives the selected receiver plant `.rad`.
* `plant_surface_flux.json` and `plant_spectral_absorption.json` include and
  agree on leaf material metadata.
* spectral absorption still reuses the surface-flux payload and does not start
  duplicate receiver tracing in Level 2.

Focused tests before Level 3 implementation:

* env/config parsing accepts only `scalar_source_weighted` and `banded_5`.
* band definitions exactly match blue, green, orange, red, and far-red ranges.
* band-specific effective coefficients are computed from the Rex profile using
  only source photons in that band.
* zero-source bands emit zero metadata and require no receiver trace.
* Level 3B banded transport runs one receiver trace per active band and does
  not rebuild or retrace baseline PPFD/uniformity artifacts.
* `plant_spectral_absorption.json` band totals reconcile with the five traced
  band fields once Level 3B execution is implemented.

Live validation after implementation:

* Proposed LED, Conventional LED, and HPS smoke runs with
  `leaf_quadrature_4`.
* At least one `mesh_patch` reference run for final workshop data.
* Compare Level 2 `opaque_occluder` versus `rex_source_weighted_trans` receiver
  incident PAR and spectral absorption metadata.
* Before Level 3B, compare planned band metadata against selected source SPD
  and Rex profile.
* Confirm baseline heatmaps, fixture overlays, 3D scatter, and assembly-viewer
  heatmap overlays are unchanged.

## Explicit Non-Goals

* no photosynthesis prediction.
* no yield prediction.
* no full 1 nm hyperspectral Radiance transport before the workshop.
* no changes to baseline PPFD/uniformity artifacts.
* no automatic regeneration of Rex optics data.
* no replacement of `plant_spectral_absorption.json` with Radiance spectral
  transport in Level 2.
* no full five-band live Radiance execution in Level 3A.
* no specular leaf transmission unless a reviewed data basis is added.

## Open Questions

* The receiver-only `.rad` file approach is implemented for Level 2; keep
  `plants.rad` stable unless a future explicitly versioned manifest change
  requires otherwise.
* Level 3A zero-source policy is implemented: skip material fitting, emit zero
  metadata, and do not require a receiver trace.
* Should banded transport use five separate octrees, or can one geometry file
  be rewritten per band with cached room/emitter inputs? The design should
  prioritize clarity and no baseline artifact multiplication.
